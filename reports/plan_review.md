## 二、结论：PLAN v1 的四个硬伤（按修复优先级）

1. **排期数学不成立（题5 Score=0，最高置信硬伤）**
   9 天工作量压进 2 天。修复：要么把 B4/B6/B8 降级为"只进矩阵不逐库建档"，要么老实改成 6~8 天；每批给出"扫读 N×10min + 深读 M×2h"的分层算式，留 20% 缓冲。
2. **没有 DoD，也没有闭环（题4=0.08 + 题11）**
   三处脱钩：B3 改造建议→无回归验收；分析结论→网文三玩法无量化收益（题10=0.90）；FINAL"完成"无判据。修复：加"完成定义"一节——①改造建议每条附后照：`jev_eval.py --compare` 在 120 条金标上一致率不降；②三玩法各定一条基线指标（稿件体检一致率≥x、梗筛选命中≥y）；③深采库 ≥N 个且 demos/ 至少 1 个复跑+复测表。
3. **"典型 demo"缺入选标准（题2=0.18 + 题7=1）**
   修复：模板第 6 节加硬条件——含可一键复跑脚本 + 有可复测的量化宣称（时延/成本/校准值至少一项）+ 与作者实际调用 API 的证据（题面/日志/视频）。复跑验收 = 原始宣称指标复测表，偏差>30% 标红回写。
4. **风险登记册漏了已发生的风险（题3=0.12）**
   github 直连超时不是假想敌，是战况。修复：risks 加"网络与获取"条目：浅克隆 `--depth 1` 为默认、jsdelivr/raw 镜像兜底、B0 产出的清单落离线缓存（csv）供断网续跑。

次级（复核档）：成本估算补一段（本地复刻拉权重磁盘/内存需求、adapter 对照实验 token 量级）；B6/B7 的优先级-排期换算规则一句话写死（消除题9 隔离项的歧义根源）。

## 三、隔离区

- `priority_coherence`：5 样本 3:2 分裂、盲审翻覆。需人工裁决的问题实质是："优先级是否必须换算成排期差异，还是允许'低优先=同时间快速扫'？"——建议直接写进 PLAN 方法论一句话，此题即消解。
